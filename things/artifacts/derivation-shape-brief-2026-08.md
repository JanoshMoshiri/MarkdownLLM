# Derivation-Shape Brief — August 2026

Input to the sitting that rules `workflow-reconciliation-precedes-new-definitions`:
what it would take, on one real specimen, for a pre-atom workflow-definition to
become a declared derivation of `universal-workflow.md`. Three routes, applied
to the specimen, with a proposed general shape. Verdicts proposed; the ruling
is the operator's.

**Read bases (direct-read, substrate vantage — same licence class as the
estate synthesis, run by operator request).** Framework root at
`commit:f52b93013b1d40bd120741b8c4c0d866d4c00748`; regulated-qms at
`commit:823e44e80430fa9d3ae8eea1b19cb180aec37924` (dated read 2026-08-27).
Per the disclosure boundary, the domain is named by its established
substitution and no controlled-document references or private identifiers
cross into this artifact.

## The Specimen

Regulated-qms's `qms-template-document-authoring` (v0.1, `evolving`, born
2026-08-26): the repeatable process for authoring a controlled document from a
pinned template while preserving structure and the human authority boundary.
Chosen because it is the estate's freshest *lived* definition — designed one
day, exercised twice within two days:

- **A closed pilot run** — full traversal, one mid-run pause at a verification
  gate, a failure loop exercised (a defective first copy regenerated and
  re-audited), attributable operator acceptance at close.
- **A live second run** — currently `paused` at `human-review`, waiting on
  exactly the attributable human act the definition declares for that stage.
- **Both runs pin `definition_commit`** — the domain adopted v3.36 revision
  binding on day one, unprompted.
- The definition's closing paragraph carries the repeatable shape's own
  clause: review findings improve the definition for later runs; they never
  rewrite the procedure a completed run claims to have followed.

Its eight stages, with per-stage performer, transition authority, and required
exit evidence declared in a table — which is the operating model's
gate-authority dimension and v3.36's executor-vs-authority doctrine, present
in a domain artifact that predates neither.

## The Mapping — specimen stages against the atom's seven decisions

| Atom decision | Specimen stage(s) | Reading |
|---|---|---|
| define-need | `scope-and-classify` | Purpose, audience, class/tier, destination, data boundary, and whether the act is creation, correction or change — the decision whole, under a domain name. |
| assess-current | `pin-source` | Current state is the source artifact's exact identity: path or ID, hash, size, modification time, register state; ambiguity stated rather than hidden. |
| define-prioritise | *collapsed into* `scope-and-classify` | The intended act and control route fix the direction. Proportionate at task radius. |
| set-mvp-target | *collapsed into* `scope-and-classify` + the slot map | The minimum acceptable outcome is structural: mapped slots filled, everything else byte-identical. A target state, stated as evidence. |
| design-plan | `distill-and-map` | Every pattern and edit slot accounted for; parts classified editable or preserve-only; requested content mapped without invented facts. |
| execute | `author-local` | Smallest safe mutation, inside the mapped slots only. |
| review-verify | `verify` + `human-review` + `close` | Subdivided: mechanical gates (structural and visual), attributable human acceptance, then outcome compared with the initiating need and residual gaps named. |
| — | `canonical-handoff` | The stage the atom does not name: the irreversible act, human-only by declared authority. The gate-authority dimension made a stage — a domain addition the atom permits, not a deviation. |

The four progression outcomes are all present and all *exercised*: forward
edges (both runs), backward edges on every stage with a failure-and-recovery
section routing each failure to its return stage (revising, exercised in the
pilot), a mid-run pause and a run paused at review now (deferring), and
close-on-rejection plus the abandon status (stopping).

**The headline finding: the derivation already happened — in behaviour.** The
specimen realises all seven decisions, carries the repeatable shape's review
clause, declares gate authority per stage, and revision-pins its runs. What is
missing is only the *declaration*: its `implements` edges point at the
domain's workflow skill and its carrying plan, not at
`universal-workflow-methodology`. The distance from full specialisation is one
edge and one mapping section. This is `a-true-primitive-is-discovered-not-authored`
playing out downstream: the domain converged on the atom's shape without
being told to, which is the strongest evidence the atom is real — and the
strongest argument that reconciliation is declaration, not rebuild.

## The Three Routes, Applied

**Route A — declare (link and map).** Add the `implements →
universal-workflow-methodology` edge; add a short Derivation section to the
definition body carrying the table above — including, explicitly, which
decisions are collapsed and why that is proportionate. Stage ids stay as they
are. Live runs untouched. Cost: minutes per definition, run by each domain's
own session. What it buys: every definition's relation to the base becomes
readable and auditable estate-wide; the atom's specialisation clause is
honoured rather than fought ("keeps the decisions and re-names or subdivides
the stages as its context demands"). What it does not buy: uniform stage
vocabulary across domains.

**Route B — restructure.** Re-mint the definition with stages renamed or
re-cut to the atom's vocabulary; live runs stay-pinned to the old revision by
default (v3.36), migration a deliberate meaning-boundary commit. What it
buys: cross-domain uniformity. What it costs: the specimen's stage names *are*
its controls — `pin-source` and `canonical-handoff` carry domain meaning a
generic name would lose — and the atom's own text licenses exactly the
renaming B would undo. On this specimen, B is fighting the spec's grain for
cosmetics. **Where B is right:** when the mapping *fails* — a decision with no
stage realising it (a definition with no review gate, no need statement).
That failure is a process gap, not a naming choice, and restructuring is then
repair, not reconciliation.

**Route C — retire.** Not applicable to this specimen (two runs in two days).
It is the route for the class the estate synthesis named at F4: the
mandated-primary lifecycle with zero runs and its approval fields at zero
uses; the delivery process at zero runs in 57 days; the weekly generator that
never ran. For each of those, the per-definition question is *first run or
honest retirement* — the demand either exists and gets its run, or the
definition is dead vocabulary and says so.

## The Proposed General Shape

Reconciliation is a per-definition pass, run inside each domain by its own
session, in this order:

1. **Map** the definition's stages against the seven decisions (the table
   above is the template).
2. **Mapping succeeds** → Route A: declare the edge, write the Derivation
   section, name the collapses. Done.
3. **Mapping fails** → the gap is a finding; Route B repairs the process (not
   the names), then A declares it.
4. **Zero runs and no demand** → Route C, retired honestly with the reasoning
   recorded.

The pattern travels by refresh — the framework ships the worked example (this
specimen's A-pass, once ratified, is the natural candidate), and each domain
walks its own definitions, because reconciliation never crosses the membrane.

**The two-homes question, answered by the specimen in practice:** the domain's
workflow *skill* holds doctrine — trust semantics, boundaries, the provenance
loop — while the *definition* holds the executable, stage-gated process, and
the definition links `implements` to the skill. Different grains, both doing
work, hierarchically related. Offered as the resolution direction for the
folded conflict; not ruled here.

## Open Questions for the Sitting

1. **Edge target:** does a definition implement the atom directly (the atom's
   own text), through the domain workflow skill (the specimen's current
   practice), or both? Rule it once; the mapping section carries it either way.
2. **Mapping completeness:** must the Derivation section name all seven
   decisions even when collapsed? Proposed: yes — naming the collapse is what
   makes proportionality auditable, and it is one line per decision.
3. **The zero-run set:** first-run-or-retire, ruled per definition in each
   domain's own pass — does the operator want those verdicts proposed in
   advance (synthesis F4 lists the candidates), or left to each domain's next
   session?
4. **Where the worked example lives:** as a framework `type: example` thing
   derived from the ratified specimen pass, or as a section in
   `domain-refresh.md`'s next version.
