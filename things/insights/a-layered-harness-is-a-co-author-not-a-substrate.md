# A layered harness is a co-author, not a substrate

**The operator's observation, stated 2026-08-08 after two grilled Cowork
sessions and a month of breach archaeology:** the bare-bones code harnesses
(Claude Code, Copilot CLI) expose agents files, skills, hooks and commands
and add nothing above them — so `AGENTS.md` is the only Definition Zero in
the room, and whatever drift exists is the agent's own. A layered harness
(Cowork; Microsoft Copilot Studio, where the operator has met the same
wall) arrives with **its own operating layer already loaded**: the domain's
Tier 0 is injected *underneath* a program that was there first and speaks
with the platform's authority. Two programs share one anchor; which wins on
a given turn is chance; that chance is the extra drift.

Predictions this frame makes, both matched by evidence:

- Drift scales with the thickness and authority of the platform layer —
  worst in Copilot Studio, real in Cowork, absent in the CLI harnesses.
- It cannot be fixed by winning the interpretation fight, because the
  platform layer is re-injected every session and outranks anything the
  domain says. The working mitigation is to **shrink what needs to win
  there**: move everything that must hold to the git-fs anchor (v3.28.0's
  session gate), and shrink the platform-side adapter's job to workspace
  assembly.

A private personal domain harvested this same insight onto its own porch
the same day (parallel discovery, operator-prompted). It is authored here
rather than imported because the disclosure boundary prevents naming that
domain in this public repo — the one-owner rule yields to the privacy
boundary, and this is the framework-side statement.
