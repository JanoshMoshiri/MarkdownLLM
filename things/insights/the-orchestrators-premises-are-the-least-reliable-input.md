# The Orchestrator's Premises Are the Least Reliable Input

## The Insight

When one agent dispatches another into a domain, **the orchestrator's stated
premises are the least reliable thing in the brief.** Not because the
orchestrator is careless, but structurally: it is working from summaries,
reports and its own earlier reasoning, while the delegate is about to read the
live corpus. Every fact the brief asserts is a claim with a timestamp; every
fact the delegate derives is current.

The operating rule that follows: **a brief's premises are leads to verify, never
givens to build on** — and the delegate should be told so explicitly, because a
capable agent handed a confident premise will otherwise honour it.

## The Evidence (one session, 2026-08-28/29)

Five corrections, all running the same direction — delegate correcting
delegator, never the reverse:

- A definition was briefed as having **zero runs**, on a two-day-old
  synthesis's authority. Two runs pinned it, both active. The delegate refused
  to write "zero runs to date" because it would have been false, and wrote the
  true residual instead.
- A cross-domain mirror was briefed as **duplicate ownership**. It carried
  `origin: external` with a full reference triple and an attributed
  verification — a correctly imported mirror. The count had selected on `type:`
  and never read `origin:`.
- A definition was briefed as unenacted across **"fifteen months of commits."**
  The corpus held 105 commits over three months; fifteen months was the reach
  of the *record*, not the stream.
- A census was briefed as having found **three decision packets never
  produced.** All three existed and were substantive; what was zero was
  *delivery*. The failure was at the handoff, not the drafting.
- A conflict was briefed with an implied remedy that would have **weakened a
  control** to suit an unattended run. The domain refused, added an independent
  validation stage instead, and named why the original control might be
  deliberate.

In each case the delegate held the corpus and the orchestrator held a report.
In each case the corpus won.

## Why It Matters for the Closed Loop

This is not a curiosity about subagents; it is the operating shape of the
dispatcher. A tick launches a session that acts as a domain's own agent, and
the launch brief carries scope, stop condition and context — but no domain
facts, deliberately. That design choice now has a reason behind it rather than
only an instinct: **the launcher is the wrong place to hold domain truth.**

It also sets the standard for what a good delegate does. The corrections above
were not the delegates being difficult. Each one refused an instruction because
following it would have written something false, and each said so with the
evidence. An agent that quietly honours a wrong premise is worse than one that
argues, precisely because nobody is watching an unattended run.

## The Operating Rules

1. **Brief with tasks and boundaries; verify facts locally.** Where a brief
   must carry a fact, mark it as a lead — *verify this, do not take it on
   trust* — and say what to do if it proves false.
2. **Re-derive from the graph, never from a report.** A synthesis is evidence
   of what was true when written. An inventory is a query. Confusing them was
   the mechanism behind three of the five.
3. **Refusing a premise is compliance, not insubordination.** Say so in the
   brief, so the delegate does not resolve the tension by obeying.
4. **A correction travelling upward is the system working.** Record it as
   evidence, not as an exception — the day the corrections stop is the day to
   ask whether the delegates have stopped reading.
