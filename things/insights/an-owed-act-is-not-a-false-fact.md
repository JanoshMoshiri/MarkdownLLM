# An Owed Act Is Not a False Fact

The git pre-commit hook refuses a commit only for what cannot disagree with
the truth: a pin that resolves to nothing, an index that differs from a fresh
build, a status the schema never declared. Those are false facts. A walk not
yet done is something else: an act still owed. Refusing a commit on it at
git would make every change wait for an agent, because git cannot tell a
person's hand edit from an agent's tool call.

The question arose on 2026-10-05, when the walk's gate turned out to bind only
in Claude Code and making git itself refuse looked like the way to reach every
harness. The operator's view was that a gate at every commit would damage the
person's experience of the workspace. The record agrees. The first
non-developer operator lost ninety minutes to friction whose vocabulary never
landed, and a refusal with a paragraph of explanation on every hand edit of a
skill is that wall made permanent.

So the rule is to enforce an owed act on the actor who owes it, in the
channel that actor reads: the agent's own tool call, through the harness's
pre-tool event, or failing that its post-write feedback. A person's edit is
never refused. It is handled the way the rest of the floor handles anything a
person leaves behind: the digest names the unwalked change, and the next
agent session walks it. A walk done late is a walk, not a lost one.

The tell for the next proposal: if a check would refuse a person for not yet
doing something, rather than for recording something false, it belongs at
the agent's boundary or in the digest, not in git.
