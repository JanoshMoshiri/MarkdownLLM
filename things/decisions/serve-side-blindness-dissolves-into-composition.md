# The Serve-Side Counterpart Dissolves Into Composition

## The Decision

**No new floor tool is built for queue row 9.** The "serve-side counterpart
to `imports-check`" that four sightings appeared to demand decomposes, on
design, into pieces that all already exist — plus one act and one convention:

| Blindness facet (synthesis F5) | Already-built answer |
|---|---|
| Freshness — a pinned import's source moved | `imports-check` `stale`, consumer-side |
| Divergence — mirror edited while pins agree | `imports-check` `diverged`, same read |
| Awareness — the face offers things never imported | `imports-check` face-coverage section; trigger condition `porch_offers_unimported` |
| Discharge — an ask was answered and the chase keeps hunting | **an ask that crosses a porch arms a watch**: `porch_offers_unimported` scoped to the source (answer id unknown), or `state_is` on a named import (answer updates a known thing) |
| Estate view — the operator's batch | `estate-check`, already "operator-axis batching" by design |

What was actually missing, measured live this session, was never a tool:

1. **The routes were never executed.** Every consumer's trust store was
   empty — `imports-check` is fully built and correctly refused every read.
   COVERAGE 0/43 and 0/101 were an unperformed clone-local trust act, plus
   one address-book class defect (five of six books launched face reads via
   bare `python`, the exact interpreter the launch doctrine warns may lack
   the floor dependency). Both repaired this sprint; the grants are staged
   for the operator.

   *Amended same session, after a live probe of the repaired route:* even
   granted, every read would still have failed — two latency defects sat
   behind the trust gate, invisible until something actually crossed it. The
   launcher's per-spawn interpreter probe cost ~12s against the membrane
   client's 10s deadline (fixed: the floor fast-paths entries resolving to
   its own installation through `sys.executable`), and the face manifest
   spawned three git processes per exposed thing — ~33s for one 46-thing
   manifest (fixed: one shared head view, two batch spawns). End-to-end
   after both: 4.3s. **A gate that has never been crossed hides every defect
   behind it** — the zero-coverage measurement was reporting the first
   obstacle, not the only one.
2. **The convention is undeclared.** The consuming domain whose
   retrospective named "serve-side discharge blindness" had four chases
   hunting work the producer had shipped five days earlier — four asks, none
   arming a watch. The synthesis's own condition ("the loop closes where
   findings are handed forward as committed things carrying dates or
   conditions") extends across the membrane unchanged: **a cross-domain ask
   is handed forward as a thing carrying an import trigger.** That is a
   domain-side authoring convention, not framework mechanism.

## Why No Build

The two governing insights each refuse one half of the imagined tool. A
producer-side consumer-enumeration violates the membrane
(`source-behind-mirror…`: one careless framing from the global index the
design refuses). A producer push violates the signal model
(`cross-domain-readiness…`: pull works because the pin exists; awareness is
a shared signal). What survives both refusals is exactly the composition
above — and it was already shipped, waiting on its trust act.

The overview-side write skill's line that serve-side notification is "this
domain's discipline alone since no tool" ages into: the *producer's*
discipline obligation is discharged by exposing the answer on its face; the
*consumer's* watch is what turns that exposure into attention. Neither side
needs the other's enumeration.

## What Would Reopen This

- A live period in which asks carrying watches still miss shipped answers
  (the convention proving insufficient, not merely unadopted).
- `porch_offers_unimported` firing too coarsely at scale — a source shipping
  many unrelated things drowning the one awaited answer. That would evidence
  a *scoping* gap in the trigger condition (e.g. tag-scoped offerings), which
  is a floor change with a named owner (`trigger-specification.md`), entered
  through `mechanical-coherence-checks-backlog`'s gate like any other check.
- Convergence of the same ask-watch pattern across three-plus corpora, which
  under `operating-model.md`'s growth rule would earn the convention a
  doctrinal seat there.
