# Decision: Workflow Reconciliation Precedes New Definitions

Made by the operator, in session, 2026-08-27.

## The situation

`universal-workflow.md` — the atom — entered the foundation on 2026-08-25
(v3.35). Every workflow-definition in the estate predates it: the atom
arrived *after* its instances. The estate retrospective synthesis surfaced
the consequence the same week (F4): defined processes sitting beside the
work rather than governing it, and no existing definition declaring how it
relates to the methodology it now sits under.

The atom's own spec says what the settled state looks like — a domain
receives the methodology with the framework and specialises it, minting
definitions linked `implements` to the spec. What is *not* yet settled is
the shape of getting there for definitions that already exist: what a
pre-atom workflow-definition must do to become a derivation of the base —
link and map its stages to the seven decisions, restructure, or retire.

## The ruling

1. **Settling the derivation shape comes first.** How existing
   workflow-definitions (and the scaffolded workflow skills, and processes
   living as prose) reconcile to the atom — so each derives from the base
   up — is the operator's ruling to make, and it has not been made. This
   decision records the sequencing, not the shape.
2. **Until it is settled, no new workflow-definitions are minted at the
   framework root.** Specifically, the operating-layer quality loop's
   definition work is held: its plan's park is re-pointed from the
   adapter-workstream sequencing to this decision.
3. **The two-homes question folds in.** Whether process knowledge lives in
   the workflow *skill* (Layer 2) or the workflow-definition *thing*
   (Layer 3) is part of the same settlement, not a separate ruling.

## What lifts it

The operator settles the shape — the likely route is one worked
reconciliation: a single existing domain definition re-derived from the
atom end to end, which becomes the pattern the rest follow via refresh.
The settlement lands as a follow-up decision or as spec change to
`universal-workflow.md` / `domain-refresh.md`, and this decision's hold on
new definitions ends with it.
