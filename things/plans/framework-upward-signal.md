# Framework Upward Signal — the substrate learns that its domains share a problem

## The retraction that opened this

Operator, 2026-08-05, on reviewing the estate re-sweep: *"It kind of makes me
retract on a comment I made earlier about the framework not needing a porch.
I think it probably does… if that information could have got to the
substrate, there would have been a clear verdict that something needed to be
done, and it was a framework problem, not a domain problem."*

The week's evidence: three defect classes each independently rediscovered in
multiple domains (the `git: branch` lie, the inert disclosure boundary, the
unregistered framework-shipped fields), each paid for locally, none visible
as a *pattern* until a deliberately-run estate sweep put them side by side.

## Doctrine constraints (all standing rulings kept)

- **Producers never learn consumers.** `who_i_know` stays empty. Nothing here
  gives any domain an outbound address book.
- **Consumption is the consumer's act.** The framework reading domain faces
  is an ordinary porch consume — the divergence primitive already arrived
  that way, triple-pinned and human-verified.
- **Batching is never an index.** Whatever aggregates is ephemeral stdout at
  the operator axis, like `triggers --estate` — never a committed registry
  of domain state in the framework repo.
- **Domain names are domain state.** The aggregate read happens locally; its
  committed residue (if any) uses role-descriptors, per the established
  discipline.

## The sketch (spec-when-foreseeable; deploy-when-felt)

1. **Domains offer frictions the way they already offer everything: exposed
   things.** A domain that hits what it suspects is a substrate problem
   exposes the insight/conflict on its face — the existing
   `framework_promotion: candidate` convention, made routine rather than
   exceptional. (The write-time exposure question shipped in v3.27.0 is the
   natural prompt for this.)
2. **The estate read gains an aggregation line.** `estate-check` (or a
   sibling `--frictions` view) reads the faces it already reads and rolls up
   candidate/friction things across sources — "same tag or near-same title
   offered by ≥2 domains" is one advisory line, not a scoring engine.
3. **The verdict stays human.** The roll-up names the coincidence; routing it
   (framework fix / domain fix / coincidence) is the operator's, recorded as
   a decision when taken — this plan never builds auto-promotion.

## Deploy trigger

The felt condition, pre-agreed: **the next same-problem-in-N-domains
rediscovery.** One more instance of paying for the same lesson twice is the
signal to build step 2 (step 1 needs no build — it is practice, available
today). Until then this stays a parked spec with its evidence attached.

## Phases (unstarted by design)

- [ ] Phase 1 — the aggregation line in the estate read (build on the deploy

- [ ] Phase 2 — walk the dark region: operator-guide + estate-mechanics
