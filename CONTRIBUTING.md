# Contributing

Thank you for your interest in this framework!

## How To Contribute

### Share Your Domain Definitions

If you've built domain definitions (instructions.md, skill.md, and prompts) for a domain not yet covered, consider contributing them:

1. Create a folder for your domain (e.g., `domains/project-management/`)
2. Include your instructions, skill, and prompt files
3. Include a README explaining your domain and how to use it
4. Add examples of real instances if helpful
5. Submit a pull request

### Improve Existing Files

If you see ways to clarify or improve the core files:

1. Fork the repository
2. Make your changes
3. Explain your reasoning in the pull request
4. Be clear about what you're changing and why

### Report Issues

If something doesn't work or is unclear:

1. Open an issue describing the problem
2. Include examples if relevant
3. Explain what you expected vs. what happened

### Share Insights

If you've used this framework and learned something useful:

1. Share your experience (issue, discussion, or blog post)
2. Document what worked, what didn't, what surprised you
3. Suggest improvements based on real-world use

## Guidelines

- **Keep it simple** — The whole point is elegant constraint and clarity. Don't over-complicate things.
- **Document thoroughly** — New domains should be well-documented with examples.
- **Be respectful** — We're building something together. Assume good intent.
- **Follow the pattern** — New domains should follow the same structure (instructions, skill, prompts, examples).

## What We're Looking For

- Domain definitions that show the framework's flexibility
- Improvements to clarity or usability
- Examples showing real-world application
- Documentation improvements
- Tools or utilities that help people use this framework

## What We're Not Looking For

- Vendor-specific integrations (we want to stay agnostic)
- Complex code solutions (this is about structure, not code)
- Breaking changes to the core pattern
- Proprietary or closed-source additions

## Getting Started

1. Read the manifesto to understand the philosophy
2. Look at the life-manager example
3. Try building something in your own domain
4. Share what you learn

## Questions?

Open an issue or start a discussion. We're all learning how to do this.
