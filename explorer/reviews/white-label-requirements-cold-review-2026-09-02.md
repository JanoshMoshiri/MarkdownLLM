# Cold review — Explorer white-label requirements (v0.5)

## Basis and verdict

Reviewed `explorer/docs/requirements.md` version 0.5 as committed at `8df56e0db09bb7a456a452dcb727908557009d59`, with the delta isolated by `git diff 9d77c57..8df56e0` (the new "Presentation and identity" subsection FR-PRES-001 to FR-PRES-007, NFR-SAFE-006, the eleven amended requirements, the five new limit rows, invariants 8 and 9, AJ-12, H6 and H7, the Section 2, 3, 4, 5 and 6 additions). Judged against the whole document and, at the same commit, the plan `things/plans/explorer-white-label-presentation-2026-09.md` (revision 1.2), `explorer/docs/design.md` v0.5, `explorer/docs/test-specification.md` v0.4, `tests/test_meta.py`, `tests/traceability.yaml`, `tests/test_http.py`, `delivery/http_server.py`, `core/eligibility.py`, `adapters/filesystem_catalogue.py`, `adapters/frontmatter_parser.py`, `delivery/static/app.css`, `index.html`, `js/app.js`, `js/views/*.js`, `windows_app.py`, `packaging/windows/explorer.nsi`, `version-info.txt`, `build.ps1`, `tools/open-explorer.sh`, the framework `.gitignore`, `_schema.yaml`, `AGENTS.md` and `tools/markdownllm/model.py`; and the gate decision `white-label-explorer-through-install-local-presentation` read from the `domain/code-architect` working tree, as instructed. At review time the framework working tree carried uncommitted edits to `design.md`, `test-specification.md`, `user-guide.md`, `test_meta.py` and `traceability.yaml`; none were read, and every finding below is against the commit. **Verdict: revise before design.** The mechanism the decision asked for is sound and the CSP widening is bounded as claimed by the code at this commit, but the requirements state the precedence between the root file and the packaged default in a way that makes the two radii mutually exclusive, state an image oracle the existing favicon route already fails, make AJ-12 assert an immutability the journey itself breaks, leave the contrast floor short of two surfaces on which the accent is text, and give the distribution profile no grammar while claiming it cannot broaden authority. Findings: **8 MUST, 12 SHOULD, 11 COULD.**

## MUST findings

### MUST-01 — Chain-level precedence makes a root file erase the packaged mark and leaves field fallbacks undefined

**Refs:** FR-PRES-002, FR-PRES-003, FR-PRES-005, FR-PRES-006, Section 3 white-label outcome, U4, AJ-12; plan "Resolution rules". FR-PRES-003 chooses one whole presentation ("first present wins") and FR-PRES-006 shows the mark image only "when the chosen presentation carries it", which only the packaged presentation can. So an organisation that distributes a Reverb-profiled build loses its logo the moment it places any `presentation.md` — even one that relabels a single tab — and gets the text mark instead. U4 and Section 3 promise both radii at once ("declared once for the install, and an installer that carries the same identity"); as written they exclude each other. The same rule leaves three observable outcomes undefined, so no oracle can be written: which value fills a field the root file declares invalidly (AJ-12 says "the default accent retained" — packaged or product?); whether a root file that is present but has no frontmatter, or no recognised field, "wins" with nothing and blocks the packaged default; and whether a field the root file omits falls to the packaged value or the product value. **Correction:** replace the first two sentences of FR-PRES-003 with: "The shell presentation shall be resolved once per discovery, field by field. For each field the first source declaring a valid value wins: the root presentation file, then the packaged default presentation embedded in the installed package, then the product default. A field the root file omits or declares invalidly takes the packaged value where the packaged presentation declares one and the product value otherwise. A root file whose frontmatter is absent, or declares none of the presentation fields, contributes nothing and is reported as a `presentation_empty` estate issue; it neither wins nor blocks the chain. The packaged mark image is a packaged-only field: a root file can neither declare it nor displace it, so a packaged mark stays in the brand-mark slot whether or not a root file is present, and a text `mark` applies only where no mark image is packaged." Amend the last clause of FR-PRES-003 and FR-PRES-005 to: "The estate response and the Settings tab shall name, for every field, the source that supplied it." Amend AJ-12 to: "sees the packaged accent — or, in a build without a packaged default, the product accent — retained beside a rejected-field issue".

### MUST-02 — Whitespace-only labels satisfy the grammar and hide the headings the gate decision forbids hiding

**Refs:** FR-PRES-002, FR-PRES-004, FR-NAV-001, Section 9 row "Presentation `name` / `tagline` / each label"; decision ruling 4. The row bounds length "after trimming" and forbids control and format characters; it sets no minimum and does not reject a value that trims to nothing. `labels: {substrate: " "}` is therefore valid, applies, and renders an empty heading over the substrate section, which is precisely the hiding ruling 4 refuses and FR-NAV-001 says "may not" happen. An empty `name` blanks the brand; an empty `substrate_kind` blanks the kind line. **Correction:** Section 9 row: "1–60 / 1–120 / 1–32 Unicode code points after trimming and NFC normalisation; a value that trims to empty is invalid; no control, format or line/paragraph separator characters". FR-PRES-002: "A field whose value is not a YAML string scalar, or trims to empty, is invalid and rejected." FR-NAV-001: "Each heading always carries a non-empty label; a rejected or empty label yields the default."

### MUST-03 — The contrast floor is measured against two surfaces but the accent is rendered as text on four

**Refs:** NFR-SAFE-006, Section 9 row "Presentation `accent` / `accent_dark`", FR-UI-001, FR-UI-003, NFR-ACC-001; `app.css`. At the commit `--accent` is the text colour of `.badge` (on `--accent-soft`, the derived colour the rule says is "computed, never supplied"), of `.commit-sha` and `.commit-back` (on the panel and page, and on `--soft` while a commit row is hovered: `.commit-row:hover{background:var(--soft)}`), and of `.markdown a`. The floor is checked "against the theme's panel and page surfaces" only, and the derivation of the soft accent is unspecified, so the badge cannot be checked at all. A supplied light accent that just reaches 4.5:1 against the page (`#f6f6f4`) renders at about 4.0:1 on the hover surface (`#e8e8e4`); a dark accent that just reaches 4.5:1 against the panel (`#181916`) renders at about 3.9:1 on `#252622` and about 3.1:1 on the default dark soft accent (`#263a32`). The product defaults pass everywhere (roughly 5.2:1 to 9.0:1), so the gap is invisible until a brand is applied and then fails the very floor NFR-SAFE-006 claims. **Correction:** Section 9 row: "exactly `#rrggbb`; contrast ratio ≥ 4.5:1 against every surface on which the accent is rendered as text in that theme — the page, the panel, the hover surface and the derived soft accent — and ≥ 3:1 against the rail surface where it is a non-text indicator". NFR-SAFE-006: "The soft accent is derived by a fixed, declared mix of the accepted accent with the theme's panel colour, and the derivation shall itself satisfy the text floor; a colour that fails on any surface is rejected with the measured ratio and the failing surface named."

### MUST-04 — "The only image the application ever loads" and AJ-12's image oracle are contradicted by the existing favicon routes

**Refs:** NFR-SAFE-003, NFR-SAFE-005, FR-PRES-006, AJ-12; `http_server.py` `_ASSETS`, `index.html`. The asset manifest already serves `/favicon.ico` and `/markdownllm-explorer.png` as `image/png`, and `index.html` says the favicon request is answered deliberately. So "no request other than the packaged mark route returns an image content type" fails before any brand exists, and "the only image the application ever loads is a packaged mark" becomes false the moment `img-src 'self'` lets the browser show the favicon it fetches on its own — which under a Reverb build is the MarkdownLLM mark in the tab, the one place the old `img-src 'none'` kept it out. The safety claim itself is bounded at this commit (see "Axes examined with no findings"); it is the statement of the oracle that is wrong. **Correction:** NFR-SAFE-003: "The only images the application ever loads are entries of its immutable packaged asset manifest — the packaged mark and the favicon — and never bytes read from a source." NFR-SAFE-005: "Same-origin image loads shall be satisfiable only by the immutable packaged asset manifest: no route outside that manifest shall serve an image content type, no manifest entry is backed by source bytes, and the rendered document pipeline emits no image element." AJ-12: "no request outside the packaged asset manifest returns an image content type". The favicon's brand assignment is SHOULD-04.

### MUST-05 — AJ-12 mutates the substrate and then asserts its snapshot unchanged

**Refs:** AJ-12, AJ-07, NFR-SAFE-001A; test spec O-IMMUTABILITY. The journey has the tester place, replace and remove `presentation.md` at the substrate root, then requires "the AJ-07 snapshot of every source is unchanged". The substrate snapshot changes by the tester's own hand at each step, so the clause is unsatisfiable as written and would be fudged or waived. **Correction:** replace the closing clause with: "The tester's placement, replacement and removal of `presentation.md` are the only changes to any source. After each such edit and before each launch the tester takes a fresh AJ-07 snapshot of the substrate; every comparison taken after an Explorer run is identical to the snapshot taken before it, and the domain sources are snapshotted once and identical throughout."

### MUST-06 — `description` has no grammar, so "invalid description" has no oracle and an unbounded string reaches the hero

**Refs:** FR-PRES-001, FR-TAB-001, Section 9. The frontmatter parser admits scalars up to 64 KiB and nothing types or bounds `description`; FR-PRES-001 makes an "invalid `description`" fall back without defining invalid, and FR-TAB-001 places the value beneath the source name on every overview. **Correction:** Section 9 row: "Declared `description` | 1–200 Unicode code points after trimming and NFC normalisation; the character rules of `tagline`; a non-string scalar or longer value is invalid". FR-PRES-001: "a `description` that is absent, not a string scalar, or fails the declared-description grammar in Section 9 falls back to the presentation's `domain_kind` label; it is shown only as the overview subtitle, and the topbar kind line always carries the kind label."

### MUST-07 — The distribution profile has no grammar, and its product name flows into paths and registry keys the safety requirements bound

**Refs:** FR-PRES-007, FR-RUN-004, NFR-SAFE-001C, invariant 9; `explorer.nsi`, `version-info.txt`, `build.ps1`. At the commit `APP_NAME` is the install-directory leaf (`$LOCALAPPDATA\Programs\${APP_NAME}`), the Start Menu folder, both shortcut filenames and, by the same literal, two `HKCU` registry key paths; product name and publisher are NSIS quoted strings and PyInstaller version-info Python literals. A profile value containing `\`, `..`, `"`, `'`, `$` or a newline moves where the installer writes or breaks the generated sources. Invariant 9 says ownership and confinement are "independent of any profile" and NFR-SAFE-001C bounds installer writes to "its per-user application files"; both hold only if the profile is constrained, and FR-PRES-007 constrains nothing. The profile is the organisation's own build input, so the exposure is to itself, but the requirement makes an unconditional claim and the build must be able to refuse a bad profile deterministically for FR-PRES-007's own pass condition. **Correction:** add to FR-PRES-007 and Section 9: "Profile `product_name` and `publisher`: 1–60 printable Unicode code points, no path separator, none of `" ' $ \ / : * ? < > |`, no leading or trailing dot or space, not a reserved Windows device name. `output_name`: a filename stem under the same rules. `icon` and `mark_image`: paths resolved relative to the profile file that must exist and pass magic-byte checks (`.ico`; PNG ≤ 256 KiB and ≤ 512×512 px). The build fails closed before generating any source on any violation. The install directory, registry keys, Start Menu folder and shortcut names derive from `product_name` only through this grammar."

### MUST-08 — The committed state fails its own trace gate; the ledger, manifest and meta test must change together

**Refs:** Section 12, Section 14; test spec §6, §11, §12, §13, O-TRACE, O-IMMUTABILITY; `tests/test_meta.py`, `tests/traceability.yaml`; NFR-SAFE-006. The meta test's regex over `requirements.md` at the commit yields 79 IDs; `test_traceability_manifest_is_exact_and_well_formed` asserts `len(requirement_ids) == 71` and manifest equality against a manifest with 71 rows, and `test_test_spec_trace_table_has_one_row_per_requirement` asserts 71 rows against a table that has 71. The mutant test pins `M01`–`M21` by regex `M(?:0[1-9]|1[0-9]|2[01])` and `range(1, 22)` while NFR-SAFE-006 and Section 14 require three new killed mutants. Section 12 forbids implementation until the ledger has no uncovered ID, so the gate is red from the moment v0.5 was committed. **Correction:** (1) `test_meta.py`: both `71` become `79`; the mutant regex becomes `M(?:0[1-9]|1[0-9]|2[0-4])` and the range `range(1, 25)`. (2) `traceability.yaml`: add rows FR-PRES-001…007 and NFR-SAFE-006 with all nine required fields; give the three new rows that Janosh owns `human_disposition: pending-human` and note that `tests/evidence/operator-acceptance.json` must then be superseded by a Reverb-cycle record, because the verifier rejects a record whose scope differs from the pending-human set; add `M22`–`M24` under `mutants`, each naming real test functions. (3) Test specification: §3 fixtures `F-ESTATE-BRANDED` (valid, absent, empty-frontmatter, malformed, oversized, duplicate-key, failing-contrast, empty-label root files; domains with declared, missing, invalid and colliding names) and `F-WINDOWS-PROFILE` (default and Reverb profiles, one malformed); §4 oracle `O-IMAGE-ROUTE` (every response's content type recorded; only manifest entries may be `image/*`); §5 tests `UT-PRES-001` (grammar, mark categories, colour grammar, contrast on every surface, field-level merge), `CT-IDENTITY-001` (entry-file identity through the confined reader, fallbacks, collisions, ordering), `CT-PRESENTATION-001` (root file, chain, issue codes and payloads), `ST-API-SCHEMA-001` (estate and settings DTO fields), `ST-HTTP-HEADERS-001` (the exact new CSP string — the current test asserts only `frame-ancestors`), `ST-SERVER-BOUND-001` (the manifest with and without a packaged mark), `ST-WIN-PROFILE-001` (generated inputs byte-identical for the default profile; names carried for Reverb; malformed profile refused), `BT-PRESENTATION-001` (shell, labels, both themes, favicon, no non-manifest image request) and `AJ-12`; §6 `M22` remove text-only rendering (killer `BT-PRESENTATION-001`, `CT-HTML-001`), `M23` remove the colour grammar (`UT-PRES-001`), `M24` remove the contrast check (`UT-PRES-001`), and a recommended `M25` add a source-backed route with an image content type (`ST-HTTP-HEADERS-001`, `O-IMAGE-ROUTE`); §11 add the eight rows, set gate check 1 to 79, and rewrite the pass conditions of FR-EST-002, FR-EST-003, FR-NAV-001, FR-TAB-001, FR-TAB-005, FR-UI-001, FR-RUN-004, NFR-SAFE-001C, NFR-SAFE-003 and NFR-SAFE-005 to the amended wording; replace every "AJ-01–11" (O-IMMUTABILITY, §5, §10 step 7, §12 step 9) with "AJ-01–12"; §13 add `visual-branded-light.png`, `visual-branded-dark.png` and `windows-profile.json`.

## SHOULD findings

### SHOULD-01 — Whether the substrate's own entry-file identity is read is undecided, and the framework's entry file declares a product description

**Refs:** FR-PRES-001, FR-TAB-001, Section 6 "Declared identity", Section 5 in-scope bullet, FR-EST-002. FR-PRES-001 is titled "declared domain identity", Section 6 says "a source's `AGENTS.md`", and FR-TAB-001 shows "the source's declared description" for every source. The framework `AGENTS.md` at the commit declares `name: MarkdownLLM Framework` and `description: A self-describing specification framework for building LLM-driven systems using markdown, YAML, and git`. Under one reading the substrate overview of a Reverb-branded estate carries the product's marketing sentence; under the other it carries the `substrate_kind` label. **Correction:** FR-PRES-001: "Declared identity is read for domains only. The substrate's name is fixed by FR-EST-002 and its overview subtitle is the presentation's `substrate_kind` label; the substrate's entry-file frontmatter is never read for presentation." Align Section 6 and Section 5 to "each domain's entry file".

### SHOULD-02 — Colliding or missing declared names are neither disambiguated nor explained

**Refs:** FR-EST-003, FR-PRES-001, FR-TAB-005, FR-EST-008. Two domains may declare the same name, or the substrate's; the rail then lists indistinguishable items, ordering follows the declared name so an edit or a parse failure reorders the rail, and the fallback is "with no error", so an operator seeing a folder name cannot learn why. **Correction:** FR-EST-003: "When two sources' NFC/case-folded displayed names are equal, or a domain's equals the substrate's, each such domain shows its folder name after the declared name in the rail and the overview." FR-TAB-005: "Settings states whether the source name is declared or a fallback and, for a fallback, the reason (`entry_missing`, `frontmatter_invalid`, `frontmatter_too_large`, `name_invalid`); a fallback is a Settings fact, not an estate issue."

### SHOULD-03 — AJ-01 and the test ledger still say **Domains**

**Refs:** AJ-01, FR-EST-003, FR-NAV-001, FR-PRES-004; test spec BT-SHELL-001 and §11 rows FR-EST-002, FR-NAV-001. The defaults are now **Substrate** and **Domain estate**, but AJ-01 has the tester see "**Substrate** above **Domains**", BT-SHELL-001 says the same, and the FR-EST-002 row's "First source is labelled Substrate" was already wrong against the 2026-08-28 amendment. **Correction:** AJ-01: "sees the substrate heading above the domains heading (defaults **Substrate** and **Domain estate**)"; FR-EST-002 row: "First source is named MarkdownLLM beneath the presentation's `substrate` heading"; FR-NAV-001 row: "Persistent rail exposes both presentation-labelled sections".

### SHOULD-04 — Favicon, tray icon, tray title and native dialog title belong to no radius

**Refs:** FR-PRES-006, FR-PRES-007, FR-RUN-005, FR-UI-001; `index.html`, `windows_app.py`. With `img-src 'self'` the browser now displays `/favicon.ico`, the product mark; the tray icon is read from `markdownllm-explorer.png`; the tray tooltip and the startup error dialog are titled "MarkdownLLM Explorer"; the menu verbs are fixed by FR-RUN-005. None is assigned. **Correction:** FR-PRES-006: "The favicon route serves the packaged mark image when one is packaged and the product icon otherwise; both are manifest entries." FR-PRES-007: "The tray icon and tooltip, the native error-dialog title and the Start Menu folder carry the profile's icon and product name; the menu verbs **Open Explorer** and **Exit Explorer** and the frozen executable filename stay the product's."

### SHOULD-05 — The vocabulary's reach is not enumerated, and the document title has no format

**Refs:** FR-PRES-004, FR-UI-001, FR-TAB-003, FR-TAB-004, NFR-ACC-001; `index.html`, `app.js`. "The Skills and Memory tab and count labels" leaves open the empty-state sentences ("say so" in FR-TAB-003), the collection `aria-label`s, the search placeholder, the session-expired message that names "Explorer", the "Read-only local view" footer, and the window title, which is a static `<title>` at the commit with nothing setting `document.title`. A tab named "Playbooks" above an empty state that says "no skills" is the visible result. **Correction:** FR-PRES-004: "The label map reaches exactly: the two rail group headings; the topbar kind line beneath the source name; the overview subtitle where no description is declared; the Skills and Memory tab buttons and count cards; and the Skills and Memory empty-state sentences, which name the label rather than the product word. Accessible names of those elements are their visible text; no `aria-label` restates a relabelled string. All other product copy keeps the product's words." FR-UI-001: "The document title is the presentation name on the estate and `<source display name> — <presentation name>` when a source is selected; it never carries a document path."

### SHOULD-06 — The product default presentation, the default tagline and the default mark are not normative

**Refs:** FR-PRES-003, FR-PRES-004, FR-UI-001, AJ-12; plan "Fields". FR-PRES-004 fixes six label defaults; nothing fixes the default name, tagline, mark or accents, so AJ-12's "default chrome" has no reference, and the plan's rule that `mark` defaults to the first character of `name` is missing. **Correction:** add to Section 9: "Product default presentation: name **MarkdownLLM**, tagline **Explorer**, mark **M**, accent `#2d6a57`, accent_dark `#8dc5ad`, labels as FR-PRES-004." FR-PRES-002: "A presentation that declares `name` but no `mark` takes the first code point of `name` as its mark when that code point satisfies the mark grammar, else the product mark. A presentation that declares `name` but no `tagline` shows no tagline line." (The tagline rule is a product decision; the alternative — inheriting **Explorer** beneath a foreign name — should be chosen deliberately, not by default.)

### SHOULD-07 — The string grammar is incomplete in the ways that matter for display

**Refs:** Section 9 rows, NFR-SAFE-006, FR-PRES-001, FR-PRES-002; `app.js` line 128. "No control or format characters" still admits line and paragraph separators (Zl, Zp), private-use and unassigned code points (Co, Cn), lone surrogates (Cs) that YAML escapes can produce, and every other whitespace; "characters" is uncounted (Python counts code points, the browser UTF-16 units); nothing requires NFC, so a decomposed `é` in a mark is a letter plus a combining mark and fails while the precomposed form passes; non-string scalars and a non-mapping `labels` are unaddressed; and the source glyph is `display_name.slice(0, 1)`, which splits an astral first character. **Correction:** Section 9: "Presentation and declared-identity strings are YAML string scalars, NFC-normalised, measured in Unicode code points after trimming, and invalid if they contain any code point of general category Cc, Cf, Cs, Co, Cn, Zl or Zp or any whitespace other than U+0020. `mark` is one or two code points of category L, N, P or S after NFC normalisation. `labels` must be a mapping — a non-mapping `labels` is rejected as one field — with each known key validated independently and unknown keys ignored. The source glyph is the first grapheme cluster of the displayed name."

### SHOULD-08 — The root file is a framework thing the floor will validate, and the framework side has not landed

**Refs:** FR-PRES-002, H6, AJ-12; plan I2; `tools/markdownllm/model.py`, `.gitignore`, `_schema.yaml`. At the commit `NON_THING_FILES` does not name `presentation.md`, `DEFAULT_EXCLUDES` does not exclude root files, `_schema.yaml` declares no `presentation` type and `.gitignore` has no `/presentation.md` entry. A minimal root file carrying only Explorer's fields is therefore validated as a thing by the pre-commit hook — missing `id`, `type`, `status`, `version` and `created` and an undeclared type are Errors — so the AJ-12 tester's file blocks the framework's next commit and appears untracked. Explorer is unaffected; the journey is. **Correction:** FR-PRES-002: "The file is also a framework thing and may carry the thing fields (`id`, `type: presentation`, `status`, `version`, `created`, `tags`); Explorer ignores them and requires none." Add H8: "The framework ignores `/presentation.md` and declares `type: presentation` before AJ-12 runs on a live checkout; until then the floor reports the file as an undeclared thing." Name both as prerequisites in AJ-12.

### SHOULD-09 — Single-instance identifiers are per user, not per root, and cross-brand coexistence is undefined

**Refs:** FR-PRES-007, FR-RUN-005, FR-RUN-006, design D-009; plan "Distribution profile"; `windows_app.py`, `explorer.nsi`. The coordinator keys the mutex and pipe on `sha256(username)`, so for one Windows user no two frozen instances run whatever their brand or root; the plan's "keyed on the substrate root" is not what the code does, and FR-PRES-007's "against one substrate root" understates it. Two differently named installs coexist on disk because `InstallDirRegKey` reads the profile's own key, and the second brand's shortcut sends `open` to the first brand's process, whose shell then appears. FR-RUN-006's "same-or-newer installer" does not cover a differently branded one. **Correction:** FR-PRES-007: "The frozen executable filename and the per-user single-instance mutex and pipe names remain the product's, so for one Windows user only one frozen Explorer runs at a time whatever its brand or root; a second brand's activation opens the running instance's browser, whichever brand it carries. A differently branded installer neither upgrades nor uninstalls an install of another brand; both may be installed, each under its own directory, registry key and shortcuts." Reconcile the plan sentence.

### SHOULD-10 — Design mechanisms the delta breaks and plan statements it contradicts

**Refs:** design §5, §8 step 6, §12, §13, §14, D-009; plan "Design allocation", "Safety boundary", "Traceability". The delta requires the design (still "Requirements v0.4") to change in named places: §8 step 6 sorts by display name before any identity exists, and the catalogue's `Source` is what `catalogue.source(id)` returns to every other use case, so identity must be resolved inside the catalogue snapshot before the sort or the estate list and the overview will disagree on a source's name; §5 `Source` has no `description`, and `EstateSnapshot` no presentation; the title, brand mark and wordmark are static in `index.html` and the accent is a CSS literal; §13 says "one teal accent"; §14 says the `M` icon is "used consistently by the executable, setup, Desktop shortcut and tray"; §12's "exact immutable asset manifest" gains a conditional entry; D-009 must say per user. The plan (revision 1.2) still says the CSP "does not change" and "`img-src 'none'` stays", numbers the profile FR-PRES-006, and claims a root-keyed mutex; the decision and requirements say otherwise. **Correction:** raise the design to 0.6 naming each change above; in the plan replace the two CSP sentences with the decision's ruling 2, renumber the traceability table to FR-PRES-001…007 plus NFR-SAFE-006, and correct the mutex sentence.

### SHOULD-11 — The performance fixture and budget do not include the new discovery reads

**Refs:** NFR-PERF-001, FR-PRES-001, FR-PRES-002; plan risk "Reading fifteen entry files slows discovery"; design §14 performance allocation. Discovery now reads every domain's entry file and the root file through the confined reader, inside the 400 ms catalogue allocation, but `estate-scale-v1` is not required to carry entry-file frontmatter or a root file, so the budget can pass without the reads it must cover. **Correction:** NFR-PERF-001: "Every fixture domain carries entry-file frontmatter with `name` and `description`, and the substrate carries a valid root `presentation.md`; the estate + first overview budget includes their reads."

### SHOULD-12 — The packaged default and mark lack a validation point, a route name and an absence rule

**Refs:** FR-PRES-006, FR-PRES-007, NFR-SAFE-005, Section 9. Nothing says whether an invalid packaged field is refused at build or reported at load, what the fixed route is, or what the route returns when no mark is packaged — all of which AJ-12's "packaged mark route" and the manifest test need. **Correction:** FR-PRES-006: "The embedded default presentation is validated at build time against the presentation grammar and contrast floor and the build fails on any rejected field; it is validated again at load, and a rejected field is reported with source `packaged_default`. The mark image is served as `image/png` at `/brand-mark.png` from the manifest; when no mark is packaged the route is absent from the manifest and returns `route_not_found`."

## COULD findings

### COULD-01 — The basis cites plan revision 1.1 at `9d77c57` while the plan is 1.2 in the same commit

**Refs:** Section 2, v0.5 bullet. The plan file changed in `8df56e0` to revision 1.2 (gate closed, Reverb identity captured), and the bullet's own content — the rulings and the test identity — comes from 1.2. **Correction:** "the white-label plan … revision 1.2 (framework commit `8df56e0`, whose revision 1.1 at `9d77c57` fixed the design intent)".

### COULD-02 — "Presentation choices" in NFR-SAFE-001C now collides with "Presentation"

## Axes examined with no findings

- **CSP boundedness as a mechanism.** At the commit the handler serves only `/`, `/health`, `/api/v1/*` and exact `_ASSETS` entries (`target.path not in _ASSETS` → `route_not_found`); every `/api/` route requires the capability header, so an `<img>` cannot fetch one; every response carries `X-Content-Type-Options: nosniff` with a non-image content type outside the manifest; `img-src 'self'` excludes `data:` and `blob:`. The decision's claim that the manifest is the sole image route holds; only its statement is wrong (MUST-04).
- **A root file influencing which image loads.** No vector: the file cannot declare, enable or select an image, only suppress the packaged one (MUST-01).
- **Injection through colours.** Exact `#rrggbb` applied through the CSSOM cannot carry `url(` or a further declaration; no finding beyond the contrast surfaces (MUST-03).
- **FR-EST-002's "named MarkdownLLM" rule.** Unchanged in substance and consistent with decision ruling 4 and invariant 8.
- **Section 5 exclusions, invariants 8 and 9, H6 and H7.** Consistent with the decision and honestly stated, subject to MUST-07's profile grammar.
- **Scope discipline.** Nothing in the delta belongs to a later increment; the deferred list matches plan I4 except the Mac launcher naming (COULD-08). The decision's six rulings are each carried by a requirement; the omissions the plan promises are the default mark rule (SHOULD-06) and the framework-side prerequisites (SHOULD-08).
- **Marks and bidirectional text.** Strong right-to-left letters are admissible and harmless; format characters that could reorder neighbouring text are excluded; the remaining gaps are separators, private-use and normalisation (SHOULD-07).
