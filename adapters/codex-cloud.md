# Codex Cloud workspace adapter

Codex selects one GitHub repository as its primary checkout. The cloud adapter
surrounds that checkout with a pinned public MarkdownLLM framework and assembles
declared secondary domains and ordinary code repositories as independent Git
clones. Each domain keeps its own AGENTS.md, skills, things and Git history.
Ordinary code repositories keep their own build and hook conventions; the
framework's `repositories/` exclusion keeps their Markdown out of its corpus.
This is a workspace transport and preparation layer.

## Build the reusable bundle

Start from a clean framework commit published to its public remote:

```powershell
& .\tools\mdllm.ps1 cloud configure domain\my-domain --harness codex
```

For an ordinary code repository selected by Codex, add
`--primary-kind repository`. The command derives the primary GitHub URL and
full framework commit from local Git. It writes a review bundle under
`.bundle-build/codex-cloud/<primary>/` containing `.codex/cloud/` and the
configuration skill. `--out <primary>` installs matching reviewed artifacts
into the primary repository; conflicting bytes are refused. `cloud check`
verifies every generated byte. `--preview` is only for a clean, unpublished
source in the private build directory and bears a release-required marker.

To add repositories, edit a copy of `environment.json` in a fresh review
directory and rerender with `--config <that-file>`. A version 2 manifest has
this shape; replace every example URL, branch, variable name and SHA with the
actual values before rendering:

```json
{
  "schema_version": 2,
  "framework_repo": "https://github.com/OWNER/MarkdownLLM.git",
  "framework_commit": "0000000000000000000000000000000000000000",
  "workspace_directory": "/workspace/MarkdownLLM/domain",
  "primary": {
    "repo": "https://github.com/OWNER/engineering.git",
    "kind": "domain",
    "credential_env": null,
    "boundary_terms_env": null
  },
  "repositories": [
    {
      "name": "quality",
      "repo": "https://github.com/OWNER/quality.git",
      "kind": "domain",
      "revision": {"commit": "1111111111111111111111111111111111111111"},
      "access": "read",
      "publication": "manual",
      "credential_env": "MDLLM_QUALITY_READ_TOKEN",
      "boundary_terms_env": "MDLLM_QUALITY_BOUNDARY_TERMS"
    },
    {
      "name": "product",
      "repo": "https://github.com/OWNER/product.git",
      "kind": "repository",
      "revision": {"branch": "main"},
      "access": "write",
      "publication": "manual",
      "credential_env": "MDLLM_PRODUCT_WRITE_TOKEN",
      "boundary_terms_env": null
    }
  ]
}
```

`workspace_directory` is the base in Codex settings, excluding the primary
repository name. It ends in `domain` or `domains` for a primary domain, or
`repositories` for primary code. Additional domains land under `domains/` and
additional code under `repositories/`, all beneath the framework root. A
secondary writable repository must declare a branch; a read reference can pin
a full commit. Repository URLs must be credential-free GitHub HTTPS URLs.
The older single-domain version 1 manifest is still accepted for existing
bundles; new rendering uses version 2.

## Git access and publication

The public framework can be fetched unauthenticated. Codex's initial checkout
proves only that the host could obtain the selected primary repository. It does
not prove that Git in setup or in the working agent can read any other private
repository, nor that it can push. The adapter offers two choices per repository:

- `credential_env: null` uses native Git credentials actually available in
  that phase; verify with `mdllm cloud probe`.
- A variable name uses an exact-repository Git credential helper. Supply the
  token value as a persistent cloud environment variable if the working agent
  needs it. Git receives it only for that HTTPS repository. The manifest and
  local Git config contain the variable name, not its value. Setup-only secrets
  disappear before the agent starts and cannot support agent-time Git access.

Use a fine-grained token scoped to the needed repository and operations. A
read-scoped token makes a reference genuinely read-only at the GitHub boundary;
`access: read` alone is an operating intention, not a filesystem sandbox.
The bootstrap does not test push authority; `cloud probe` tests only remote
read. A domain's ignored `.boundary-terms` may be supplied by
`boundary_terms_env`; no coverage is claimed when it is absent. The file is
not tracked, so decide how long private terms may remain in Codex's cache.

The primary clone gets `mdllm.publication=pr` and `mdllm.sync=observe` locally.
Its automatic sends are disabled, and estate sync observes its selected HEAD
without moving it. Review the primary result through Codex's diff/PR route.
Secondary repositories do not inherit that PR route. `publication: manual`
disables their automatic sends and leaves a separate, deliberate publication
step. `publication: declared` is valid only for a writable domain; it leaves
that domain's existing literal `git.autopush: true` in charge and grants no
authority on its own. Failed or unpushed secondary results are reported by
`cloud status` and must be checked against each remote. No publication path
forces, resets, rebases or silently resolves divergence.

## Configure and run

Commit the reviewed artifacts to the primary repository and make them
available on its default branch. Codex prepares its environment cache on that
branch before selecting a task branch. In the Codex Cloud environment settings,
select that primary repository, set its workspace base to the manifest's
`workspace_directory`, choose Manual setup, and enter:

```text
bash .codex/cloud/bootstrap.sh
```

Use `bash .codex/cloud/bootstrap.sh maintenance` for cached maintenance.
Setup downloads the exact public framework commit with full history, checks
the container and exclusions, restores a missing explicit primary `origin`
when needed, assembles secondary clones and installs the shared floor only in
domains. It refuses dirty cached secondary repositories, changed pins,
foreign paths and changed manifests; review draft state before resetting a
cache. It preserves the host-selected primary HEAD, index and tracked files.
The private framework virtual environment pins PyYAML 6.0.3.

After the working agent starts, use the framework runtime from the assembled
workspace (for example, `<framework>/.venv/bin/python <framework>/tools/mdllm.py`):

```text
cloud probe <primary-checkout-path>
cloud start <primary-checkout-path> --repository <domain-name>
cloud status <primary-checkout-path>
```

`cloud start` performs a bounded estate sync, emits the selected domain's
Tier-0 contract with an integrity trailer, and leaves skill loading to that
domain's AGENTS.md. Run it separately for each domain whose seat is used.
Setup logs are not model receipt. The session gate is deferred at setup and
enforced at the first real commit. Existing `.codex/hooks.json` trust and
execution must be inspected separately with `mdllm doctor . --harness codex`.

Changing a framework pin, manifest or checked-in bootstrap requires an
intentional cache reset. A changed primary repository file alone may not
invalidate the cached setup. The `configure-codex-cloud` skill can perform
the conversational configuration and supported Codex settings UI steps; it
uses no private environment API. A real cloud task is still required to
verify setup, agent-time Git access, model receipt, hooks and publication on
this product surface. The OpenAI Agents API hosted environment is a different
route.
